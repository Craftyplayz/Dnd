## 1. Conventions

- **Units:** feet everywhere. 1 SVG user unit = 1 ft. Grid cell = 5 ft.
- **Axes:** x east, y south, origin = map's north-west corner. Map spans `[0, grid.widthFt] x [0, grid.heightFt]`.
- **Rotation:** degrees, clockwise (same as SVG `rotate()`), about the element's `position`.
- **Compass:** north = −y. Light `azimuth` is the compass bearing the light comes *from* (315 = north-west).
- **Determinism:** rendering and layout never use `Math.random()`, `Date`, `performance.now()` or iteration over unordered state. Same scene → byte-identical SVG. Randomness comes only from `createRng(element.seed)` (or `scene.seed` for terrain) and `rng.fork(label)` sub-streams.
- **Modules:** plain ES modules, no frameworks, no npm runtime deps. Static relative imports only, with the `.js` extension (`import { h } from '../core/svg.js'`). No dynamic `import()`, no top-level side effects other than definitions. JSON is imported only as `import X from '../schema.json' with { type: 'json' }`.
- **UI text:** no emoji anywhere. Icons, if any, are inline SVG.
- **Browser storage:** only via `src/storage/draft.js`, always inside try/catch.
- **Browser target:** current Chromium and Firefox.

## 2. Scene model

One JSON document. The renderer is a pure function of it. Full schema: `schema.json`.

```jsonc
{
  "meta":    { "name": "Riverside Ruin", "id": "riverside-ruin", "version": 1, "description": "...", "createdAt": "ISO", "updatedAt": "ISO" },
  "grid":    { "cellFt": 5, "widthFt": 120, "heightFt": 120, "visible": true, "color": "#000000", "opacity": 0.22 },
  "terrain": { "base": "grass", "variation": 0.5, "tint": "#hex (optional)" },
  "regions": [ /* polygons: pond, tall-grass, rubble, ground */ ],
  "paths":   [ /* polylines with width: road, stream, ruined-wall, fence, cliff-edge */ ],
  "objects": [ /* props: tree, bush, boulder, rock-cluster, wagon, crate, barrel, tent, campfire, building, bridge */ ],
  "labels":  [ /* label */ ],
  "lighting":{ "azimuth": 315, "elevation": 45, "intensity": 0.6, "time": "day|dusk|night", "ambient": "#hex (optional)" },
  "seed": 4417,
  "constraints": [ /* stated distances, section 2.3 */ ]
}
```

`constraints` is an addition to the top-level keys in the brief; it is how "a distance I state must be exact" survives edits.

### 2.1 Elements

Every element in `regions`, `paths`, `objects`, `labels`:

| Field | Meaning |
|---|---|
| `id` | `^[a-z][a-z0-9-]{0,47}$`, unique across all collections and constraints |
| `type` | key of `x-elementTypes`; its `kind` must match the collection (`object`→`objects`, `path`→`paths`, `region`→`regions`, `label`→`labels`) |
| `name` | human name shown in the UI ("Overturned wagon") |
| `layer` | one of the type's `layers` (default `layer`) |
| `position` | `{x, y}` ft. Objects/labels: centre. Paths/regions: origin of `params.points` |
| `rotation` | degrees clockwise |
| `size` | `{w, h}` ft. Objects: footprint before rotation (`w` along local x). Paths/regions/labels: **derived** by `normalizeScene` (bounding box of points, paths padded by width) — read it, never rely on writing it |
| `params` | type-specific, schema in `x-elementTypes[type].params`. Extra keys are allowed and ignored |
| `seed` | uint32. Default `hash32(id) ^ scene.seed` |
| `locked` | optional; layout never moves a locked element |
| `notes` | optional free text |

Paths and regions store geometry in `params.points: [[x, y], ...]` **relative to `position`, before rotation**. World point = `toWorld(el, p)` from `geom.js`. Dragging a path changes only `position`.

### 2.2 Element types

Defined in `schema.json` → `x-elementTypes`. Per type: `kind`, `layer`, `layers`, `cat` (collision category), `footprint` (`circle`|`rect`, objects), `footprintScale`, `blockedBy` (categories it may not overlap), `minGapFt`, `sizeFt {min, typical, max}` (objects, `[w, h]`), `widthFt {min, typical, max}` (paths), `description` (fed to the LLM), `params` (schema with `default`s).

Adding a type = one generator file `src/generators/<type>.js` + one entry in `x-elementTypes`. `build.py` regenerates the registry and fails if the two sets differ. The server builds the LLM type list from `x-elementTypes`, so prompts update automatically.

### 2.3 Constraints

```json
{ "id": "c-stream-tower", "kind": "distance", "a": "watchtower", "b": "stream", "ft": 30, "measure": "edge", "direction": "east", "text": "stream runs 30 ft east of the watchtower" }
```

- Meaning: `distanceFt(a, b, measure) == ft` (section 4), within **0.05 ft**.
- `measure`: `edge` (default) = visual edge to visual edge (path edges include width, trees use the canopy). `center` = centre point (objects, labels), centreline (paths) or polygon (regions).
- `direction`: where `b` lies relative to `a`. The layout solver moves `b` along this unit vector (`any` = along the centre-to-centre line). `a` is the anchor and never moves for this constraint.
- The LLM writes a constraint for every distance the user states. Removing an element with `applyPatch` removes its constraints.

### 2.4 Normalisation (`normalizeScene`, mirrored in `server.py`)

Fills, never overwrites: `constraints/regions/paths/objects/labels` → `[]`; `seed` → 1; grid `color` `#000000`, `opacity` 0.22; terrain `variation` 0.5; lighting `elevation` 45; constraint `measure` `edge`, `direction` `any`; element `rotation` 0, `seed` `(hash32(id) ^ scene.seed) >>> 0`, `params` `{}`, `name` = id, `layer` = type default, missing params from schema `default`s (deep copy). Always recomputes `size` of paths/regions (bbox of points, rounded to 0.01, paths + width on both axes, min 0.1) and labels (`w = len(text) * fontFt * 0.55`, `h = fontFt * 1.2`, rounded to 0.01). `hash32` = FNV-1a 32-bit over UTF-8 bytes; vectors in `tests/cases.json`.

## 3. Validation

`checkScene(scene) -> { ok, errors: [{path, message}], scene }` = normalise, then validate. Both validators (JS and Python) must give the same verdict on every case in `tests/cases.json`.

JSON Schema keywords implemented (everything else is ignored): `type` (string or list; `integer` = finite whole number; **booleans are not numbers** — in Python check `bool` before `int`), `enum`, `const`, `properties`, `required`, `additionalProperties` (bool or schema), `items` (single schema), `minItems`, `maxItems`, `minimum`, `maximum`, `minLength`, `maxLength`, `pattern` (search semantics as written; patterns are anchored), `$ref` (`#/...` only). `default`, `description`, `title` and `x-*` are annotations.

Semantic checks after the schema pass: grid sizes multiples of 5; ids unique across elements and constraints; `type` known and in the right collection; layer allowed; params valid against the type schema; regions ≥ 3 points; object and label `position` inside the map (inclusive; a path or region `position` is only the origin of its points and may lie outside); constraint `a`/`b` exist and differ.

Never accept `NaN`/`Infinity` (Python: `json.loads(..., parse_constant=reject)`). Reject any scene or patch value nested deeper than 64 levels (`MAX_DEPTH` in `patch.js`). Patch existence checks use own keys only (inherited names such as `constructor` never exist); `__proto__` is never a valid token.

`touchedIds` is conservative: an op on a whole collection touches every element in it before and after, and an op on `/constraints/...` touches that constraint's `a` and `b` before and after.

## 4. Geometry (`src/core/geom.js`)

- `shapeOf(el, {scale=1, center=false})` → `{core: 'point'|'line'|'poly', pts, r, closed}`. Circles (footprint `circle`, or `building` with `params.shape == 'round'`): point core, `r = (w+h)/4*scale`. Rects: 4-corner polygon scaled about the centre. Paths: polyline core, `r = width/2*scale`. Regions: polygon.
- `footprintOf(el)` = `shapeOf` at the type's `footprintScale` (collision footprint).
- `distanceFt(a, b, 'edge'|'center')` — the distance used by constraints, the measure tool and the report.
- `gap(A, B)` edge gap of two shapes, `overlaps(A, B, tol=0.01)` positive-area overlap (touching is not overlap), `coreDistance`, `pointInPoly`, `boundsOf(el)` world AABB, `toWorld/toLocal`, `rotatePt`, `DIRECTIONS`, `snap(v, step)`, `snapPosition(el, pos)` (drag snap: bbox corner to 5 ft when rotation is a multiple of 90, else centre to 2.5 ft).

**Collision rule** (layout and report): elements `A`, `B` with at least one object collide when `A.blockedBy` contains `B.cat` or `B.blockedBy` contains `A.cat`, and `overlaps(footprintOf(A), footprintOf(B))`. Required spacing between such pairs: `gap(footprintOf(A), footprintOf(B)) >= max(A.minGapFt, B.minGapFt)` (warning only). Bounds: an object's collision footprint must lie inside the map (canopies may overhang the edge).

## 5. Generators (`src/generators/<type>.js`)

```js
// src/generators/wagon.js
import { h } from '../core/svg.js';
export default {
  type: 'wagon',                 // must equal filename and an x-elementTypes key
  render(el, rng, ctx) {         // -> SVGElement (usually a <g>)
    ...
  },
};
```

- `el` is a normalised element (all param defaults filled). `rng = createRng(el.seed)`. Use `rng.fork('planks')` etc. so features are independent.
- Draw in **local coordinates**: objects centred on (0,0) spanning `[-w/2, w/2] x [-h/2, h/2]` before rotation; paths/regions draw `el.params.points` as given. The renderer wraps the result in `<g class="el" data-id data-type data-layer transform="translate(x y) rotate(r)">` — generators never apply `position`/`rotation` themselves.
- Must not throw for any schema-valid element. Pure: the same `el` gives the same output.
- `ctx` (built by the renderer, one per render call):

| Field | Meaning |
|---|---|
| `ctx.doc` | `Document` used for `createElementNS` (pass to `h(tag, attrs, children, ctx.doc)`) |
| `ctx.scene` | the full scene (read only) |
| `ctx.light` | `{ azimuth, elevation, intensity, time, shadowDir: [dx, dy] }` — `shadowDir` is the world unit vector shadows fall along: `(-sin az, cos az)` |
| `ctx.shadow(el, heightFt)` | local-frame `[dx, dy]` shadow offset for an object of that height: `shadowDir * heightFt / tan(elevation)`, capped at `2 * heightFt`, rotated by `-el.rotation` |
| `ctx.def(id, build)` | registers a shared `<defs>` child once per SVG (`build()` returns the element, its `id` attribute is set to `id`); returns `"url(#id)"`. Generator-private ids are prefixed `g-<type>-` and must not depend on element ids unless the def is per element (then `g-<type>-<el.id>-<name>`) |
| `ctx.palette` | shared colours, section 5.1 |

### 5.1 Painted style (shared by agents 1 and 2)

- Top-down, hand-painted VTT look: layered fills (dark base, mid tone, highlight on the lit side), slightly irregular outlines (`smoothD` with rng jitter), thin darker rim stroke at 0.25–0.4 ft, no pure black outlines, no hard flat clip-art fills.
- Light from `ctx.light`: lit side = toward the light (`-shadowDir`). Every raised object draws its own soft shadow first: same silhouette, offset by `ctx.shadow(el, heightFt)`, fill `#000`, opacity `0.28 * intensity + 0.1`, `filter="url(#f-shadow)"`.
- Natural variation: size jitter ±8%, hue/lightness jitter ±6%, irregular outlines; no two trees identical.
- Renderer-provided defs (agent 1 creates them in every SVG; generators reference only these ids):

| id | Purpose |
|---|---|
| `f-shadow` | Gaussian blur, stdDeviation 0.6 ft, generous filter region |
| `f-shadow-wide` | blur 1.6 ft (canopy and building shadows) |
| `f-rough` | edge roughening (`feTurbulence` + `feDisplacementMap`, scale ≈ 0.6 ft) |
| `f-grain` | multiplies fine noise into a fill (painted texture) |
| `f-soft-edge` | blur for terrain blending (stdDeviation ≈ 2 ft) |
| `p-grass`, `p-forest-floor`, `p-dirt`, `p-mud`, `p-sand`, `p-gravel`, `p-stone`, `p-stone-floor`, `p-moss`, `p-crops`, `p-snow`, `p-swamp`, `p-water-shallow`, `p-water-deep`, `p-wood` | patterns, `patternUnits="userSpaceOnUse"` in ft |

All filters use `filterUnits="userSpaceOnUse"` and `primitiveUnits="userSpaceOnUse"` (or objectBoundingBox fractions), so they look the same at any export scale. Never use pixel-dependent values.

- `ctx.palette` (agent 1 defines in `src/render/palette.js`, exported `PALETTE`): `{ grass:[dark, mid, light], foliage:[...], pine:[...], bark:[...], wood:[...], woodDark:[...], stone:[...], dirt:[...], water:[...], cloth:[...], fire:[...], thatch:[...], slate:[...] }`, each a 3-tone array of `#rrggbb`.

## 6. Renderer (`src/render/index.js`, agent 1)

```js
export function renderScene(scene, opts = {}) -> SVGSVGElement
// opts: { doc = document, layers = {terrain:true, ground:true, low:true, objects:true, canopy:true, labels:true, grid:true, lighting:true},
//         grid (bool, overrides scene.grid.visible), viewBox: {x, y, w, h} ft (default whole map),
//         widthPx, heightPx (set width/height attributes; default none), interactive (default false) }
export function mountView(container, bus) -> View
```

- Root `<svg xmlns viewBox="0 0 W H">`, `shape-rendering="geometricPrecision"`. Children in this order, each a `<g data-layer="...">`: `defs`, `terrain` (base texture with variation, edge blending under ground regions), `ground`, `low`, `objects`, `canopy`, `lighting` (ambient tint by `time`, campfire light pools, vignette — non-interactive, `pointer-events="none"`), `labels`, `grid`. Hidden layers are omitted (export) or `display="none"` (view).
- Within a layer: collection order `regions, paths, objects, labels`, then array order.
- Every element group: `<g class="el" data-id="{id}" data-type="{type}" data-layer="{layer}" transform="translate(x y) rotate(r)">`. Interactive views give element groups `pointer-events="visiblePainted"` and `cursor: pointer`; terrain, lighting and grid are `pointer-events="none"`.
- A generator that throws is caught: render a red dashed bbox placeholder and `console.error`; never break the whole map.
- Grid: lines every 5 ft, `stroke=grid.color`, `stroke-opacity=grid.opacity`, width 0.08 ft.

`View` (live, pan/zoom):

```js
{
  svg,                       // live root <svg>
  overlay,                   // <g data-layer="overlay"> above everything, same ft coordinates. The editor draws its
                             // handles in its own <svg class="bms-overlay"> over #map instead (drawing inside the
                             // filter-heavy map svg forced full repaints), so this group is normally empty.
  setScene(scene),           // re-render (cache per element by JSON key; must stay < 100 ms for 300 elements after first paint)
  setLayerVisibility(name, visible), getLayerVisibility() -> {name: bool},
  screenToFt(clientX, clientY) -> {x, y}, ftToScreen(x, y) -> {x, y},
  getViewport() -> {x, y, w, h, zoom},   // visible ft rect; zoom = CSS px per ft
  setViewport({x, y, zoom}), fit(),
  elementIdAt(clientX, clientY) -> id | null,   // topmost visible element
}
```

Pan/zoom: wheel zooms about the cursor (zoom clamped 1–200 px/ft); pan with middle-drag, right-drag, or Space+left-drag. **Left button without Space belongs to the editor.** Emits `view:changed`.

## 7. Patch format (`src/core/patch.js`, mirrored in `server.py`)

RFC 6902 subset: ops `add`, `remove`, `replace` (no `move`, `copy`, `test`). JSON Pointer paths, `~0`/`~1` escaping. **Exception:** in `regions`, `paths`, `objects`, `labels`, `constraints` the second token is the element **id**, not an index.

| Path | Meaning |
|---|---|
| `/objects/wagon-1/position` | replace a field of element `wagon-1` |
| `/paths/stream/params/points/2` | standard pointer inside the element |
| `/objects/-` (add) | append a new element (`value` is the full element; `size`, `seed`, `layer`, defaults are filled by normalisation) |
| `/objects/new-id` (add, id absent) | same as append |
| `/objects/tree-3` (remove) | delete element; constraints referencing it are deleted too |
| `/terrain/base`, `/lighting/time`, `/meta/name`, `/grid/visible`, `/constraints/c-1/ft` | top-level fields |

Root (`""`) cannot be targeted. Moving an element between collections = `remove` + `add`. Application is all-or-nothing on a deep copy; the result is normalised and validated before commit (`store.commit`). `touchedIds(scene, ops)` lists element ids an op list touches.

Shows `res.summary` after applying.

- **Generate box** in `#topbar`: description textarea (+ optional width/height in ft) → `api.generate` → `layout.layoutScene(scene, {fix: true})` → `store.set(result.scene, {label: 'Generate', source: 'generate'})`. Shows elapsed seconds while waiting (calls take 20–180 s).

- **Keys** (ignored while typing in inputs): Delete/Backspace delete selection (one commit), Ctrl+Z undo, Ctrl+Y and Ctrl+Shift+Z redo, Escape, V select tool, M measure tool, arrows nudge 5 ft (Shift 1 ft).

- **Side panel** (`#sidepanel`, collapsible via a `.panel-toggle` button): Layers (checkbox per `VIEW_LAYERS`), Distances (renders the layout report; clicking an item selects its ids), Properties (selected element fields; numeric edits commit), Usage (today's requests / cap and estimated cost), Scenes (list from `api.listScenes`, open → `store.reset`, delete with confirm, Save, Save as, Download JSON, Upload JSON via `src/storage/file.js`).

## 9. Layout engine (`src/layout/index.js`, agent 4)

```js
layoutScene(scene, { fix = true }) -> { scene, report }   // pure, deterministic, never deletes elements
checkScene(scene) -> report                                 // no changes
neighbours(scene, ids, radiusFt = 40) -> element[]           // elements (not in ids) with distanceFt edge <= radius to any id
summarizeScene(scene) -> { name, widthFt, heightFt, terrain, lighting, counts: {type: n}, elements: [{id, type, name, x, y, w, h, rotation}] }  // numbers rounded to 0.1, max 400 elements
```

Fix order: (1) normalise; (2) clamp objects so their collision footprint is inside the map; (3) solve constraints in array order by moving `b` along `direction` (bisection on the move distance until `|distanceFt - ft| <= 0.01`); `a` and `b` of every constraint, `locked` elements, paths and regions are **pinned** for step 4; (4) resolve collisions by moving the later non-pinned object of each colliding pair to the nearest free spot on a 2.5 ft lattice spiral up to 30 ft away (deterministic order); unresolvable → report error, do not move; (5) build the report.

```js
report = {
  ok: bool,                         // no 'error' items
  items: [{ level: 'ok'|'warn'|'error', kind: 'constraint'|'collision'|'bounds'|'spacing'|'size'|'lane'|'cover'|'bridge',
            ids: string[], message: string, expectedFt?: number, actualFt?: number }],
  moved: [{ id, from: {x, y}, to: {x, y}, reason }],
  stats: { elements, coverPct, lanes: { westEast: bool, northSouth: bool } }
}
```

- `constraint`: one item per constraint, `ok` when within 0.05 ft else `error`, message like `Stream is 30.0 ft east of Watchtower (stated 30 ft)`.
- `collision` error per colliding pair; `spacing` warn; `bounds` error; `size` warn when an object is outside its type's `sizeFt.min/max` (either orientation) or a path width outside `widthFt`; `bridge` warn when a bridge does not overlap water, or a road crosses water with no bridge within its crossing.
- `lane`: rasterise to 5 ft cells; a cell is blocked when its centre is inside a collision footprint of an `object`/`structure`, a `wall`, a deep stream/pond, or a cliff. BFS for a 5 ft-wide route west↔east and north↔south; `warn` if missing.
- `cover`: % of open cells within 30 ft of cover (trees, boulders, rock clusters, wagons, buildings, walls, crates, tents); `warn` under 60%.

| Mode | Scale | Grid |
|---|---|---|
| `vtt` | 140 px per 5 ft (28 px/ft) | scene setting |
| `print` | 300 DPI, 1 in = 5 ft (60 px/ft) | scene setting |
| `screen` | current viewport at `devicePixelRatio` CSS px | scene setting |
| `nogrid` | 28 px/ft | hidden |

- Output size for full-map modes: exactly `widthFt/5 * pxPerSquare` x `heightFt/5 * pxPerSquare`.
- Rasterise `renderScene(scene, {layers: all except overlay, grid, viewBox, widthPx, heightPx})` → `XMLSerializer` → Blob URL → `Image` → canvas. Above 8192 px on a side render 4096 px tiles (each tile = same SVG with a sub-`viewBox`) and stitch with a streaming PNG encoder (`CompressionStream('deflate')`, CRC32), so no single canvas exceeds 4096 px. If the total exceeds 400 megapixels, confirm with the user first.
- Filename `<slug(meta.name)>_<W>x<H>.png`, W/H in grid squares of the exported area, e.g. `ruined-watchtower_30x24.png`. Screen mode uses the visible area rounded to whole squares.
- Labels use `font-family: Roboto, sans-serif`; exported images may fall back to the system sans font (fonts are not embedded).

## 12. HTTP API (`server.py`, agent 4)

Python stdlib only (`http.server.ThreadingHTTPServer`, `urllib.request`, `hmac`, `hashlib`, `secrets`, `json`). Binds `0.0.0.0:$PORT` (default 8080).

### 12.1 Common rules

- JSON responses: `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`. All responses: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`. Page responses add `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' data:; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com data:; img-src 'self' data: blob:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`.
- Errors: `{"error": {"code": "...", "message": "human readable", "details"?: [...], "retryAfterSec"?: n}}`; 429s also send `Retry-After`.
- Mutating methods (POST, PUT, DELETE) require `Content-Type: application/json` (415 `unsupported_media_type`) and, when an `Origin` header is present, `Origin` must match the request host (403 `bad_origin`). Bodies over `MAX_BODY_BYTES` (default 2 MiB) → 413 `payload_too_large` without reading the body. Invalid JSON → 400 `bad_json`.
- Auth: every route except `GET /login`, `POST /login`, `GET /healthz` requires a valid session. `/api/*` without a session → 401 `unauthorized`; pages → 302 to `/login`. The auth check runs before routing (an unknown path without a session also gets 401/302, never 404).

| Code | Status |
|---|---|
| `bad_json`, `bad_request`, `bad_scene_id`, `invalid_scene` | 400 |
| `unauthorized`, `invalid_password` | 401 |
| `bad_origin` | 403 |
| `not_found` | 404 |
| `payload_too_large` | 413 |
| `unsupported_media_type` | 415 |
| `rate_limited`, `daily_cap`, `locked_out` | 429 |
| `llm_invalid` (output failed validation twice), `llm_refusal`, `llm_error` (upstream error/timeout) | 502 |
| `llm_not_configured` (no `ANTHROPIC_API_KEY`), `busy` (connection limit) | 503 |
| `method_not_allowed` | 405 |
| `too_many_scenes` | 409 |
| `internal` | 500 |

### 12.2 Auth

- Startup: exit with a clear message and status 2 if `APP_PASSWORD` is unset or shorter than 12 characters. Missing `ANTHROPIC_API_KEY` is a warning; LLM routes then return 503.
- `GET /login` → HTML login page (inline, same design tokens, posts JSON with `fetch`); if already logged in, 302 to `/`.
- `POST /login` `{password}` → 200 `{ok: true}` + cookie, or 401 `invalid_password` `{attemptsLeft}`, or 429 `locked_out`. Compare `hmac.compare_digest(sha256(given), sha256(APP_PASSWORD))`.
- Lockout: 5 failures (`LOGIN_MAX_FAILS`) from one IP within 15 min → that IP is refused for 15 min (`LOGIN_LOCKOUT_MIN`), even with the right password. Success resets the count. Client IP = socket peer; with `TRUSTED_PROXY=1`, the right-most `X-Forwarded-For` entry.
- Cookie `bms_session=v1.<sid>.<exp>.<sig>`: `sid` 32 hex random, `exp` unix seconds (now + 7 days), `sig` = hex HMAC-SHA256(secret, `v1.<sid>.<exp>`). Attributes `HttpOnly; SameSite=Strict; Path=/; Max-Age=604800`, plus `Secure` when `COOKIE_SECURE=1`. Secret = `SESSION_SECRET` env, else read or create `DATA_DIR/session_secret` (64 hex chars, file mode 600).
- `POST /logout` → clears cookie. Sessions are stateless; rotating the secret revokes all.
- `GET /api/session` → `{authenticated: true, model, limits: {ratePerMin, dailyCap}}`.

### 12.3 Scenes

Files `DATA_DIR/scenes/<id>.json`. `id` must match `^[a-z0-9-]{1,64}$` before any filesystem access (400 `bad_scene_id`); the resolved path must also sit inside the scenes directory. Writes are atomic (temp file + `os.replace`). Max 500 scenes (409 `too_many_scenes`).

| Route | Request | Response |
|---|---|---|
| `GET /api/scenes` | — | `{scenes: [{id, name, updatedAt, widthFt, heightFt}]}` newest first |
| `GET /api/scenes/{id}` | — | `{id, scene}` or 404 |
| `PUT /api/scenes/{id}` | `{scene}` | normalise + validate (400 `invalid_scene` with `details`), set `meta.id = id`, `meta.updatedAt = now`, keep/set `createdAt` → `{id, updatedAt}` |
| `DELETE /api/scenes/{id}` | — | `{ok: true}` or 404 |

### 12.4 LLM routes

`POST /api/generate` `{description (1–4000 chars), widthFt?, heightFt? (ints, multiples of 5, 20–600), seed? (uint32)}` → `{scene, usage, attempts}`. The returned scene is normalised and valid; the client still runs the layout engine.

`POST /api/edit` `{instruction (1–2000), selectedIds (≤ 50), selected (elements), neighbours (≤ 200 elements), summary, scene}` → `{ops, summary, usage, attempts}`. The server validates `scene` (400 `invalid_scene`). The model sees `selected`, `neighbours`, `summary` and the instruction (with `selectedIds: []` it sees the whole scene instead). The server applies `ops` to a copy of `scene`, normalises and validates, and when `selectedIds` is non-empty checks `touchedIds ⊆ selectedIds ∪ neighbour ids ∪ added ids`. Any failure → one retry that shows the model its output and the errors → still failing → 502 `llm_invalid` with `details`. The scene on the client is never touched by a failed edit.

Model output formats (JSON only; the server strips ``` fences and takes the outermost `{...}`): generate → a full scene object; edit → `{"ops": [...], "summary": "one sentence"}`.

### 12.5 Limits and usage

- `RATE_LIMIT_PER_MIN` (20): per session id, sliding 60 s window over `/api/generate` + `/api/edit` → 429 `rate_limited`.
- `DAILY_REQUEST_CAP` (300): all users, UTC day, persisted in `DATA_DIR/usage-daily.json` `{date, requests, inputTokens, outputTokens, costUsd}` (atomic write, lock). Checked and incremented before calling the model (a retry is the same request). Over cap → 429 `daily_cap` "Daily limit reached (300 requests). Resets at 00:00 UTC."
- `UsageSnapshot` = `{date, requests, cap, remaining, inputTokens, outputTokens, costUsd, model}`. `GET /api/usage` returns it; LLM responses include it as `usage`.
- `DATA_DIR/usage.log`: one JSON line per model call `{ts, endpoint, model, attempt, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, costUsd, ok, error?, session}` where `session` = first 12 hex of sha256(sid). Never log the API key, password, cookie, or prompt text.
- Cost = tokens × `config.json` `pricing[model]` (`inputPerMTok`, `outputPerMTok`, `cacheReadPerMTok`, `cacheWritePerMTok`).

### 12.6 Anthropic call

`POST {ANTHROPIC_API_URL or config.apiUrl}` (default `https://api.anthropic.com/v1/messages`), headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`, `anthropic-beta` from `config.betas`. Body: `model` (`CLAUDE_MODEL` env → `config.model` → `claude-sonnet-5-5`), `max_tokens` (`config.maxTokens[route]`), `stream: true`, `system: [{type: "text", text, cache_control: {type: "ephemeral"}}]`, `messages`, `output_config: {effort: config.effort[route]}`, `fallbacks: config.fallbacks` when set. Parse SSE: concatenate `text_delta`s of `text` blocks (ignore `thinking`), usage from `message_start` + `message_delta`. `stop_reason == "refusal"` → 502 `llm_refusal`, no retry. `max_tokens` → treat as invalid output (retry once asking for a more compact result). No `temperature`, no assistant prefill. The key is read from the environment only and is never sent to the browser or logged. `ANTHROPIC_API_URL` exists so tests can point at a local fake upstream.

**Alternative backend `LLM_BACKEND=claude-cli`** (default `api`; local single-user use with a Claude subscription). Each model call runs `CLAUDE_CLI` (default `claude`, resolved with `shutil.which`) as `-p --output-format json --model <model> --system-prompt "You produce JSON only, exactly as instructed in the input." --tools "" --no-session-persistence --strict-mcp-config --setting-sources ""`, argument list without a shell, cwd a fresh empty temp dir, timeout `LLM_TIMEOUT_SEC` (default `config.timeoutSec`), environment = the server's minus `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `APP_PASSWORD`, `SESSION_SECRET`. The rendered system prompt and the conversation (including a retry's previous output and errors) go to stdin as one text with section headers. The JSON on stdout maps to the same flow: `result` = the text; `is_error`, a nonzero exit, unparsable output, a timeout or a missing executable → 502 `llm_error` (scrubbed); `stop_reason` `refusal` → `llm_refusal`, `max_tokens` → invalid output (retry). Usage tokens are logged as usual with `costUsd: 0`. Rate limit and daily cap apply; `llm_not_configured` is only returned for `api` without a key. `usage.log` lines, `UsageSnapshot` and `GET /api/session` carry `backend`.

System prompts live in `prompts/generate.md` and `prompts/edit.md` and contain the placeholders `{{ELEMENT_TYPES}}` (rendered from `x-elementTypes`: type, kind, cat, sizes/widths, params with enums and defaults, description) and `{{RULES}}` (`prompts/rules.md`: size realism, spacing, cover, lanes, constraints). They require JSON-only output.

## 13. Build and packaging (agent 5)

`python build.py` (stdlib only):
1. Regenerate `src/generators/index.js`: `export const GENERATORS = { <type>: <import> ... }` from `src/generators/*.js` except `index.js` and `_*.js`, sorted. Fail if the set differs from `x-elementTypes` keys or a file's `type` differs from its filename.
2. Bundle all modules reachable from `src/main.js` into one `dist/index.html`: rewrite relative specifiers to bare `@app/<repo-relative path>`, emit `<script type="importmap">` mapping each to a `data:text/javascript;base64,...` URL; JSON imports become `export default <json>;` JS modules and the `with { type: 'json' }` clause is removed. Entry `<script type="module">import '@app/src/main.js';</script>`.
3. Inline CSS: `src/styles/base.css` first, then other `src/**/*.css` sorted, into one `<style>`.
4. Template: `src/index.html`; replace the region between `<!-- BUILD:CSS -->...<!-- /BUILD:CSS -->` and `<!-- BUILD:JS -->...<!-- /BUILD:JS -->`.
5. Deterministic output. Exit non-zero on any error.

Docker: multi-stage on `python:3.12-slim`; build stage runs `build.py`; final image holds only `server.py`, `config.json`, `schema.json`, `prompts/`, `dist/`; non-root user; `ENV DATA_DIR=/data`; `VOLUME /data`; `EXPOSE 8080`; `HEALTHCHECK` hitting `/healthz` with Python urllib.
